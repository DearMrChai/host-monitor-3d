# 本地服务与数据源（§七 ~ §八）

> 本文件是 host-monitor-3d 文档的一部分，文档地图见根目录 [README.md](../README.md)。

## 七、设备清单落成本地文件（`serve.mjs` + `设备清单.json`）

`file://` 双击打开时浏览器**不能写盘**，所以"编辑同步改配置文件"必须过一次本地 HTTP：

```
cd E:\DSH-workspace\代码仓库\host-monitor-3d
npm i                 → 装 three（校验用）+ ssh2（探测用），只装在本目录
node serve.mjs        → http://127.0.0.1:8123/monitor-wall.html
                        http://127.0.0.1:8123/silhouette-shelf.html
```

- 只监听 `127.0.0.1`，零依赖，静态文件限定在本目录（带目录穿越防护）。
- `GET /api/devices` 读 `设备清单.json`（首次没有就按内置默认生成一份）；`PUT /api/devices` 写回，
  先写 `.tmp` 再改名，避免中途崩溃留下半个 JSON。
- 页面一打开就从文件起列表；之后任何编辑（改名 / 换档 / 电源 / 系统 / 地址 / 用户名 / 增删 / 排序）
  去抖 400 ms 写回一次，弹窗里那行"来源"会显示最近写入时间。
- **落盘字段七个**：`name / tier / power / os / host / user / pass`。**`pass` 是明文**——
  2026-09-23 你明确说"账号密码可以先写进配置文件"，所以收。这条推翻了派单里
  "凭据不要出现在任何产物里"那一句（只对这个本地文件生效），代价写清楚：
  **`设备清单.json` 从此是敏感文件** —— 不要拷进仓库、不要进分享包、不要贴进群或截图。
  ATX 那台已按你给的实验机填好（142 的地址/用户/口令），**其余七台凭据为空、继续走模拟**。
  现在清单里是八台：笔记本 / ITX / mATX / ATX / E-ATX / NAS / 交换机 / 路由器。
- **`探测记录.log`**：每次 `/api/probe` 追加一行 `时间  OK|FAIL  主机  错误首行`，
  **不记用户名与口令**。有它在场，"有没有人偷偷连过某台机器"是可以查证的，不用凭谁的记忆说。
  截至 2026-09-23 下午，该文件三行：一行 `FAIL 127.0.0.1`（我自测打本机 sshd，认证失败），
  两行 `OK`（目标是 142，见 §八）。**除这两次之外没有连过任何机器。**
- 读文件时做归一：档位不在表里退回 mATX、字符串截断、布尔归一、非对象项丢弃——手改坏 JSON 不会把页面搞崩，
  最坏情况回落到内置默认并在来源行标出。
- 用 `file://` 打开仍然可用（编辑只在内存，来源行会写明没连上服务），两种打开方式共存。
- 依赖只有两个，都写在本目录 `package.json`：`ssh2 ^1.17.0`（探测）+ `three 0.170.0`（让 node 能 import
  两个几何模块做校验；页面走 CDN importmap，跟这个依赖无关）。`node_modules/` 已进 `.gitignore`。
  立项时是从 `00-暂存\素材` 整份拷过来的，装前装后工作区根的 `package.json` / `pnpm-lock.yaml`
  md5 与 `node_modules` 条目数完全一致 —— 当初装 ssh2 没有顺手改写外层任何东西。

## 八、数据来源分流 + 脚下脉冲

- **分流只有一条判据**：`连接地址 + 用户名 + 密码` 三格全填 = 这台走 SSH；缺任一格 = 模拟。
  凭据现在会落盘（见 §七），所以**刷新后这台仍是"可采"态**，chip 会显示 `待抓，仍模拟`（红），
  点一下"连通性测试"就转成实测。之前"刷新后必须重输密码"的代价随明文落盘一起消掉了。

- 走实测的那台，一帧快照能给的：主机名 / 系统 / **核数** / 1 分钟负载 / **内存总量与已用** / 根分区容量 / 有没有卡（`nvidia-smi`）。
  给不了的：**各核分布、频率、温度、磁盘与网络的读写速率**——一次快照没有速率。
  所以 `hwOf(d)` 只把核数 / 内存容量 / 显卡张数换成实测值，其余继续模拟，并且**每一节的抬头挂一枚 chip 标明出处**：
  `负载/核数 实测 · 分布分摊`、`容量 实测`、`一帧实测`、`未抓到 GPU`（红）、`模拟（快照无速率）`、
  `抓不到，仍模拟`（红）、`模拟`。红标出现即代表这台确实在走 SSH 分支且没拿到数据。
- 传输层是 `ssh2`，已装在 `素材\node_modules`（`^1.17.0`）。`serve.mjs` 用 `await import("ssh2")`，
  换机器没装时每条请求明确回 `本机未安装 ssh2`，所以"抓不到 → 标红"这条分支不碰任何真实机器也能验。
  `/api/probe` 挡了非本机来源（`Origin` 必须是 127.0.0.1/localhost），用户名/口令不回显、不进日志，
  只有"时间 + 目标主机 + 成败 + 错误首行"进 `探测记录.log`。
- **一条硬约束被这次改动带出来，记死**：`probe()` 里一个笔误（`ssh2` 写成未定义的名字）在 Promise 里抛出，
  会变成 unhandled rejection，**把整个 serve 进程带走**，页面只看到一个断掉的连接（http=000）。
  路由现在包了 try/catch：任何一次探测失败只回 500/502，服务不倒。
- **第 5 项"拿 142 真实抓一帧"已开并已跑通（2026-09-23 下午，用户口头放行"所以你可以开"）**。
  两次实测都从页面里点"连通性测试"走完整链路（浏览器 → `/api/probe` → ssh2 → 142 → 一帧 → 看板），
  弹窗回读：`主机名 infer-142`、`系统 Ubuntu 24.04.4 LTS`、`核心数 12 核`、`1 分钟负载 0.15 / 0.02`、
  `内存 5.8 / 15.5 GB`、`磁盘（根分区）61% 已用`、`GPU 0% · 显存 21943/22528 MB · 53°C`。
  `探测记录.log` 里对应两行 `OK`（目标是 142，地址只存在于 `设备清单.json`，不抄进这份文档；
  日志本身只有时间/主机/成败，没有用户名与口令）。
  **交叉核对**：这台抓到帧后负载 = 0.02/12 ≈ 0%，于是它的分级钉在 `IDLE 0%`、脚下是绿色慢脉冲，
  而旁边四台模拟机在 30~77% 之间游走 —— 说明分级读的是真数、不是随机数。
  用户先前自己点过一次（比日志还早），那次也通。

**采集频率**（设置 → 性能监控，`MONITOR_SETTINGS.intervalMs`）：
一个 `setInterval` 同时驱动两处 —— 右侧看板的数值推进、每台设备的"负载 → 分级"判定。
放同一个定时器是刻意的：否则会出现面板已换新、脚下脉冲还挂在旧状态。滑杆 200~5000 ms（步进 100，默认 800），
改完立刻重启定时器并落 `localStorage["hm.mon.v1"]`。
**SSH 那一帧不受这个节拍管**：一次快照要在远端跑好几条命令（超时上限 8 s），按 800 ms 去戳真机是虐待，
所以仍然是"点连通性测试 / 双击聚焦"时抓一次。

### 脚下脉冲（照你给的"种子版"参考复刻，只取脉冲）

`PULSE_SETTINGS` 四格 + 三级分级 `STATES` 全部照参考的结构，机箱仍用我们自己的版本：

| 项 | 值 | 说明 |
|---|---|---|
| `pulseStartBrightness` | 0.95 | 环刚发射时的不透明度 |
| `pulseEndBrightness` | 0.03 | 飞到最远端时的不透明度 |
| `upParticleBrightness` | **0.22**（参考是 0.35） | 向上粒子亮度，见下面那条"为什么会饱和成白柱" |
| `travelK` | 6（滑杆 2~16） | 扩散半径 = **机器本体**底面半径 × 6 |
| `STATES` | IDLE 绿 `0x00ff41` / 3.0 s / 单发<br>ACTIVE 黄 `0xffcc00` / 2.0 s / 双发<br>ALERT 红 `0xff0033` / 1.2 s / 三连发 | 爆发内延迟 0 / 0.2 / 0.35 s，所以听感是"嘟 / 嘟嘟 / 嘟嘟嘟" |

**换到毫米口径时我改了三个量，每个都有理由**：

1. **半径按"机器本体"算，不按整套桌面**：桌面组合里显示器 + 键鼠把包围盒摊到 860 mm 宽，
   拿它当 footprint 的话一圈能罩到邻居家脚下（台间距才 2140 mm）。所以 `rebuild()` 里
   取 `getObjectByName('chassis') || getObjectByName('laptop') || model` 再量一次，
   NAS / 交换机 / 路由器这三档整个模型就是本体。mATX 那一档实测 footprint 半径 174 mm → 环最远 1.04 m。
2. **向上粒子默认压到 0.22**：参考那套是"相机 48 单位看 6 单位的机器"，粒子在屏上稀疏；
   这里全景离地十几米，一束 60 粒挤在几个像素宽里，`AdditiveBlending` 直接**饱和成白柱、颜色全丢**。
   滑杆上限仍是 1，要更亮自己拖。
3. **没带 UnrealBloomPass**：派单禁 `three/examples/`，所以参考里那层光晕糊不出来，
   整体比参考暗一档是预期、不是掉效果。要真做辉光得先解掉那条红线（或自带一份 bloom）。
   贴图为补偿全部走白色程序化渐变（`softDotTexture` 圆柔光 / `tailTexture` 横向拖尾），
   颜色由 `material.color` 按分级染，三档共用同两张图 —— 运行时 canvas，**不是外部素材**。

**分级阈值是我先定的，等你聊**（`STATES` 里那三个 `max`，改一处即可、别处不动）：
`≤35% 空闲 / 35~70% 活跃 / >70% 高负载`。负载的来源：抓到帧 = `1 分钟负载 ÷ 核数 × 100`，
没帧 = 本地随机游走（每台相位不同，避免五台同色同拍）。
**换档那一刻名字那行标注会跟着变颜色**（绿/黄/红 + `● 高负载 74%`），所以不用盯着脚下也能核对分级没算错。

**实测读数（八台全开、稳态）**：屏上恒有 14~17 个环 + 14~17 束上飘（`scene` 里 Points 30~34 个），
粒子总数 1.0~1.6 万，`updatePulses` 的 **CPU 提交时间 ≈ 1.2~2.3 ms/帧**（约 0.086 ms/千粒）。
连推 30 s 队列不增长（`排队` 全 0 或瞬时 1~2，即"正在三连发中途"）——**没有泄漏**。
⚠ 这只是 CPU 侧，GPU 的填充/合成开销没量（后台标签页量它必然出假数），**帧率要开人眼**。
自检钩子 `__hm().pulseRun(n)` 手推 n 帧（×50 ms）并回投上面这些数；
它的时钟基准取 `max(上次探针, clock.elapsedTime)` 再往前推，**跨次调用保持单调**——
上一版每次从 0 起，把延迟队列甩到"未来"、虚拟时钟永远追不上，读数假 stuck（我差点把它记成 bug）。

**参考里没取的部分**：屏幕跟着闪那一下（你说"仅脉冲"）、`EffectComposer` 那套后期、
它自带的三台占位设备与调试面板（参数改由设置弹窗那四格滑杆进 `setPulseSetting`）。
