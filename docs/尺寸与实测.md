# 尺寸与实测（§一 ~ §四）

> 本文件是 host-monitor-3d 文档的一部分，文档地图见根目录 [README.md](../README.md)。

单位约定：**1 世界单位 = 1 毫米**。几何一律按"立着"建（底面 y=0、x/z 居中、正面朝 +z），
躺/站由调用方一个 `rotation` 决定。每个模型的包围盒严格等于下表毫米值。
盒子极值由**特征件单独定义**（宽=侧板、高=顶窗、深=电源灯端面），外壳在每个贴合面各退 1~2 mm，
所以任何两个朝外的面都不重合——重合就是深度缓冲里的同一个深度，整块面积会闪。见 §四之三。

抓取时间：2026-09-23。

**三处必须交代的判断**（厂商没给轴向标签，或者给的数不含我要画的东西）：

1. **NAS 的轴是官方标的**：那一行写着"高 x 宽 x 深"，所以 220=高、148=宽、182=深，不是我挑的。
   自洽性核对过：5 个盘位排在 220 的高度里 = 44 mm/位，3.5" 盘连托盘正好这个量级。
2. **交换机的 100 与 25 谁深谁高是我挑的**：官方只写 `158×100×25`。取 **深 100 / 高 25**，
   因为 8 口一排要占掉 158 的宽度（8 × 19 mm 间距 = 152，正好），而 25 高的扁盒是这类金属壳交换机的常态。
3. **路由器那两个数两家顺序不一样**：TP-LINK 写 `270×56×245`，pconline 写 `270×245×56`。
   取 **宽 270 / 机身高 56 / 深 245**（卧式机身 + 天线在尾部竖起）。
   ⚠ **这一档的包围盒高度不等于规格数**：4 根天线竖起来后实测高 **144.2**，厂商那个 56 只是机身。
   所以 `_verify.mjs` 的规格表里 **故意不收 routerAX**（收了就是逼我把天线压矮去凑数），
   只收 NAS 与交换机两档。移植时按"机身 56"对齐，别拿 144.2 当规格。

**看板上这三台少哪几节，是按"有没有这个东西"决定的**，不是按好不好看：
`TIER_HW` 里填 0 的那一项整节不建 —— 交换机没有 CPU/内存/磁盘（只有 8 个口，当 8 张网卡看）、
路由器没有磁盘/显卡、NAS 没有显卡。XDR5410 的内存规格页没给数字，所以那格留 0（= 不显示），
**没编一个数**。判据在 `panelKeys()`，重建用签名比对（`panelSig`），不然每一拍都会把整块面板重做、
把用户点开的卡片选中态冲掉。

### 之三 · 机箱正面的三个平面（这一版修的就是它）

正面从前到后是三层，**每层差 1 mm，谁都不跟谁齐平**：

| 层 | z（以 mATX d=347.5 为例） | 谁 |
|---|---|---|
| 最外 | `d/2` = 173.75 | `power-led` 外端面（规格深度就是它定的） |
| 中间 | `d/2 - 1` = 172.75 | `front-panel` 前表面（正面看得见的那一大片） |
| 最里 | `d/2 - 2` = 171.75 | `case-shell` 前表面 |

同理：宽度极值由 `side-window` 定（**侧板在 −x，也就是正对机箱时的左手边**，跟真机塔一致；
外壳就往另一侧退 1 mm，x 从 −w/2+1 到 +w/2）、高度极值由 `top-vent` 定（外壳顶退 1 mm）。
`case-foot` 上端埋进外壳 2 mm（底面照旧 y=0），免得脚顶跟外壳底面共面。
E-ATX 的 `io-panel` 比竖肋再退 1 mm（`d/2-5.5`）：那一档的竖肋够高，顶到 io-panel 的高度区间里，
同平面就是共面。格栅 / 竖肋 / io-panel 一律在 `d/2-4.5`，跟前面板内表面差 0.5 mm 以上。

**代价（照实记）**：正对着看时，剪影**左边少 1 mm、顶上少 1 mm**（外壳在 −x 退了 1 mm，
而定义极值的侧板 / 顶窗都缩在深度方向里，正视角下被透视挡住；右边反而是齐到极值的）。
205 宽里少 1 mm = 0.5%，440 高里少 1 mm = 0.23%，亚像素。
**包围盒三个数一个没动**（表里 205.0×440.0×347.5 等全部照旧）。

**这一改的直接后果，用正面相机打 40×40 射线量出来的**（`S`=外壳 `P`=前面板，每格记"第一个撞到谁"）：

```
改前（mATX 正面，节选）      改后
 1 ·SSSSSSSSSSSSSSSSSSSS·     1 ······················
 2 ·SPPPSSSSSSSSSSSSPSSS·     2 ··PPPPPPPPPPPPPPPPPP··
 3 ·SSSPPSSSSSSPPSSSPSSS·     3 ··PPPPPPPPPPPPPPPPPP··
```

改前那张花斑就是闪烁本身：两个面在同一个深度，谁赢由三角形顺序决定，相机一动就换边。
改后整片统一归 `front-panel`（三档分别有 1044 / 1320 / 1359 格从 `case-shell` 变成 `front-panel`），
`case-shell` 在 40×40 采样里一格不剩——它前表面只剩左右各 3~4 mm 的边条，比一个格（约 5.5 mm）还窄。
颜色上正面那一大片从 `case-shell` 的键换成 `front-panel` 的键，是**变暗一点**，不是换色相。
定点射线也确认电源灯现在稳定在最前（改前它跟前面板齐平，被吃掉）。

**侧板翻到左手边之后，页面默认视角（az=−0.62，前左上方）里它才看得见**：同一台相机、
60×60 首击，`side-window` 从 **0 格变成 mATX 11 / ATX 14 / E-ATX 23 格**（正对照＝把模型转 180°
复现旧的右手边摆法，那一面只有素板 `case-shell`）。剪影宽度不变，因为机箱左右对称。

**还剩一条登记，不算缺陷**：世界 AABB 初筛会报 `laptop-screen ↔ screen-linux-bar(x)` 同侧重合，
是 75° 转轴把世界包围盒糊出来的假阳性。在屏盖局部系里实量：玻璃 y 6.90~7.90，
所有内容块 y ≥ 13.05，隔 5.15 mm；内容块两两同面重叠面积 0.00 mm²。
**教训跟笔记本朝向那条一样：斜着的件别拿世界包围盒判共面，要回到它自己的局部系。**

内容层按"屏在哪个面"分两套朝向（`screenContent(sw, sh, t, 'lid'|'monitor')`）：
笔记本屏的法线是局部 **+y**，显示器屏的法线是 +z，所以同一个 helper 要能出两种摆法。

**开盖笔记本的朝向是这一版踩过坑的地方，移植时照抄这个结论**：屏盖转轴 `rotation.x = +75°`
之后，屏盖局部 **+y 那一面才朝观众**（世界方向 0, 0.26, 0.97），局部 −y 是屏盖背壳。
玻璃和内容层必须在 +y 侧；装到 −y 侧的话正面只能看见一块屏盖内侧（黑的），
真屏幕躲在背面，而且画面左右是镜像的。
判这件事别只量包围盒——包围盒两种装法完全一样。要在正面架一台相机打射线，
问"第一个撞到的是谁"（本版就是这么抓出来的：`screen-win-b → screen-win-a → laptop-screen → laptop-lid`）。

**为什么玻璃和内容层之间要留几毫米，而不是贴着放**：单位是毫米、相机远端 6~9 万，
普通深度缓冲在这个跨度下分辨率很差（near=1 时 9000 距离上一个深度台阶约 4.8 mm），
只差零点几毫米的两层会被判成同一深度，整块屏幕就在两个颜色之间闪。
所以玻璃到内容层给了 5 mm 量级的真间隙、内容层之间 1.0~1.2 mm，页面侧另外开了 `logarithmicDepthBuffer`。
**移植时如果仓库那边的 renderer 没开对数深度，这几毫米的间隙是唯一的保险，别再往回收。**
Windows 那两块叠着的窗口（`screen-win-a` / `screen-win-b`）在画面上是重叠的，
所以它们分了层（`screenContent` 的 layer 参数，每层错开 2 倍厚度）；
同层重叠 = 共面 = 必闪，加块的时候要么分层要么别叠。
机箱正面是同一个病、同一味药，只是那边靠"三个平面各差 1 mm"解决（§四之三）——
