## A. 安全修复（评审实证的两个高危 + 限速）

### A1. 静态文件不再泄出明文凭据
- **在哪里看**：服务端口上直接请求静态文件。
- **怎么操作**（在能连上端口的机器上）：
  ```
  curl -s -o NUL -w "%{http_code}" http://<IP>:8123/devices.json
  curl -s -o NUL -w "%{http_code}" http://<IP>:8123/probe.log
  ```
- **验收合格标准**：两个都回 `404`（修复前 `devices.json` 回 200 且内容是明文 user/pass）。
  顺带确认正常页不受影响：`http://<IP>:8123/` 回 `200`。

### A2. 畸形 URL 不再打崩服务
- **在哪里看**：服务进程是否存活。
- **怎么操作**：`curl -s -o NUL -w "%{http_code}" "http://<IP>:8123/%ZZ"`，然后立刻再开一次正常页。
- **验收合格标准**：畸形请求回 `400`；连发几个后服务仍存活（修复前第一个 `/%ZZ` 就让整个进程退出，页面 `ERR_CONNECTION_REFUSED`）。

### A3. /api/probe 限速（防借道滥用）
- **在哪里看**：`POST /api/probe` 的返回码。
- **怎么操作**：
  ```
  # 清单外的任意主机（应从严）：连打 4 次
  curl -s -o NUL -w "%{http_code}\n" -X POST -H "content-type: application/json" -d '{"host":"8.8.8.8","user":"x","pass":"","os":"linux"}' http://<IP>:8123/api/probe   # ×4
  # 清单内的机器（监控目标，聚焦加速用）：同一 10s 窗口内还能再打
  curl -s -o NUL -w "%{http_code}\n" -X POST -H "content-type: application/json" -d '{"host":"<清单里的某台>","user":"…","pass":"","os":"linux"}' http://<IP>:8123/api/probe   # ×3
  ```
- **验收合格标准**：清单外第 4 次回 `429`（前 3 次 200）；同一窗口切到清单内还能过 2 次（第 7 次 429）。
  正常使用（双击补抓、连通性测试）打不满，不应出现 429。

## B. 采集提速（本次需求："展开后数据要活起来"）

### B1. 并行抓帧：一轮 ≈ 最慢那台
- **在哪里看**：`GET /api/frames` 响应里的 `rounds` 字段（页面控制台 `fetch('/api/frames').then(r=>r.json()).then(j=>console.log(j.rounds))`）。
- **怎么操作**：打开看板页，看 `rounds.startedAt / finishedAt` 的差，或看 `probe.log` 一轮里各台时间戳。
- **验收合格标准**：一轮从"各台耗时之和"（4 台实测 20~45 s）变成"≈最慢那台"（Windows ~11 s / linux ~1.6 s）；
  各台在 `probe.log` 里时间戳几乎同时（不再隔 1.2 s 排队）。

### B2. 聚焦加速：展开看板时被看那台每 5 s 抓一帧
- **在哪里看**：看板（双击某台展开后的右侧面板）头部"实测 HH:MM:SS"时间戳；`probe.log` 里那台的出现频率。
- **怎么操作**：主人浏览器（127.0.0.1 或 HM_OWNER 名单内）双击展开一台填了地址的机器，盯着时间戳/数值；
  收起（双击空白）后再看 `probe.log` 频率。
- **验收合格标准**：
  - 展开时：linux 台时间戳约 **每 6~10 s** 变一次、Windows 台约 **每 11~15 s** 变一次（受探测时长限制）；
    数值（CPU/内存/GPU）随帧跳动，"活"起来。
  - 收起后：该台回到正常轮节奏（不再 5 s 一次）。
  - 观众（HM_ALLOW 名单内非 owner）展开：不触发 5 s 抓取（`/api/probe` 回 403，页面不显示"抓不到"）。

### B3. 无人访问停采：2 分钟没人看就停，访问即恢复
- **在哪里看**：服务端控制台日志；`GET /api/frames` 的 `idle` 字段；`probe.log` 是否还在长。
- **怎么操作**：
  1. 打开页面让它转一两轮，然后**关掉页面**，等 2~3 分钟。
  2. 看服务端日志：应出现 `[serve] 无人访问 …s，停止采集轮（有人打开页面即恢复）`，且 `probe.log` 不再追加。
  3. 重新打开页面：日志恢复轮转，`probe.log` 继续追加。
  4. 或直接命令行验证：关页面等 2 分钟，`curl http://<IP>:8123/api/frames` 第一次响应 `"idle":true`、第二次 `"idle":false`。
- **验收合格标准**：无人访问 ≥2 分钟自动停（机器零打扰）；一有人打开页面立即恢复，数在秒级回来。

### B4. 抓帧间隔下限 1 s
- **在哪里看**：设置弹窗 → 采集频率 → 第二根滑杆"抓帧间隔"。
- **怎么操作**：把滑杆往左拖到底。
- **验收合格标准**：滑杆最低能到 **1 s**（修复前是 3 s）；值会写进 `settings.json` 的 `monitor.probeEveryMs`。
  ⚠ 验收后记得拖回默认 15 s——1 s 连轴转对真机是持续打扰，不是日常档位。

### B5. 帧上墙更快（PULL 1 s）
- **在哪里看**：页面 `__hm().probeState()`（控制台）显示"每 1000 ms 一趟"。
- **怎么操作**：控制台 `__hm().probeState()`。
- **验收合格标准**：显示每 `1000` ms 一趟（修复前 2000）。
