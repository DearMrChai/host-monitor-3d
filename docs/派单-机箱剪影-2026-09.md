## 硬约束（违反一条，产物就用不上）

1. **绝对不碰仓库。** `E:\DSH-workspace\代码仓库\host-monitor\` 全程只读；连一个文件都不要写。你的东西只进上面 `00-暂存\素材\`。
2. **零外部素材。** 不许 `.glb`/`.gltf`/贴图图片/外部字体/three.js 自带的 `examples` 模型。所有形状用程序化几何拼：`BoxGeometry` `CylinderGeometry` `ExtrudeGeometry` + `Shape`。仓库里一个加载器都没有，导进来的东西一律不接。
3. **版本钉死 `three@0.170.0`**（仓库是 `^0.170.0`）。HTML 里用 importmap 走 CDN；不要 `latest`——那边能渲染、这边不能，是最难查的一种返工。
4. **几何必须是纯函数，不是摆好的场景。** 每个模型一个导出函数，签名：
   ```js
   // 单位：世界单位。返回 THREE.BufferGeometry（或一个 Group 但只含 geometry+本地变换）。
   export function chassisATX() { /* ... */ }
   ```
   **`node --input-type=module -e "import('...set2-geometry.mjs').then(m=>console.log(Object.keys(m)))"` 必须能跑通** ——模块顶层不许碰 document/window/renderer。这条就是验收，因为仓库的自检正是这么在 node 里跑 `three` 的。
5. **姿态不要写死在几何里。** 几何一律按"立着"建（底面在局部 y=0、x/z 居中），躺/站由调用方一个 `rotation` 决定。墙上今天是横放口径，142 其实是立着的塔式机——两种都要能拿，一份几何就够。
6. **尺寸给真数，别照我的表凑。** 每个模型把真实毫米尺寸换算成世界单位，并把毫米原值和出处写进 `尺寸表.md`。**不要为了让四档"看着分得开"去改真实比例** ——分不清由尺子说，不由手感说。
7. **颜色随便，反正我不带。** 你的示例需要多亮、什么色相随你画；移植时零件面色一律换成仓库 `lib/palette.js` 的键。仓库有条只许降不许升的颜色预算，多一个 hex 字面量我就得删一个。
8. **不要加这些**：配置项、档位注册表、按机器读参数的逻辑、插件式扩展点。仓库的设计是"能单独改 ≠ 能配置"，四档写死就是对的。
9. 真实 IP / 凭据 / 机器名不要出现在任何产物里（`尺寸表.md` 也不要写"这是我家 142"）。
