**新三台里那些灯（`nas-led` / `switch-led` / `switch-led-pwr` / `router-led`）跟 `power-led` 同一条待遇**：
页面试版把它们一起塞进 `parts.leds`，关机一起变暗 —— 移植时它们该吃 palette 的同一个"指示灯"键。

模型不给材质（`new THREE.Mesh(geometry)` 用 three 默认材质），所以这里一个颜色字面量都没有。
开关机 / 系统那些颜色是**页面试版自己上的**，移植时按 palette 键重写，别照抄试版的 hex。

试版页面的外壳（也不是几何，不用移植）：顶部一条 40 px header，左边写 **Host Monitor**、
**设备间距 `SPACING = 2140 mm`**：地面网格一格 250 mm（`GridHelper(24000, 96)`），2140 让 mATX↔ATX
这一对的净空正好 5 格（原来 2400 = 6 格）。相邻四对的实测净空 = 5.90 / 5.15 / 5.01 / 4.73 格，
最紧的是 E-ATX↔ATX（它俩最宽），没有互相贴住。改这个数只动货架疏密，不动任何机器的真实尺寸。
⚠ 那张 `GridHelper` 已于 2026-09-23 被点阵涟漪地面替掉（见下面"地面与雨"那段），
所以上面这些"几格"是**当时那张 250 mm 网格上的读数**，如今屏幕上没有格线可对；
点阵自己的格距是 133.3 mm（300 参考单位 / 180 细分 × 80），跟 2140 没有整数倍关系，别拿它当尺子。

**2026-09-23 加分区之后，那一排变成了四堆**（`monitor-wall.html` 那页；剪影架那页仍然是一排）：
四个区**同一个尺寸**的格子 `ZONE_FIELD = 4400 × 3200 × 1150 mm`，过道 `ZONE_AISLE = 900`，
默认摆位 `(x, z)` = 算力 `(-2650,-4100)` / 储存 `(2650,-4100)` / 网络 `(0,0)` / 终端 `(0,4100)`
（"一排到下一排"= `ZONE_PITCH = 区深 + 过道 = 4100`）。**网络区就是地图中心**（2026-09-23 第二次重排：
相对方位没动，整张图平移了半个 Z 间距，把网络区钉在原点）—— 全景的取景中心由包围盒现算，
所以这一挪顺带把"画面中心"和"地图中心"对上了。区内一行最多 3 台、间隔 `CLUSTER_SPACING = 1400`（5.6 格），
满了换行（行距 `CLUSTER_ROW_GAP = 1800`）。**区内为什么不用 2140**：四台算力按 2140 排就是一堆 6.4 m 宽，
四堆摆一起地图要 14 m，全景退到那个量级机器又成灰点了 —— 要更疏只改那两个常量，机器尺寸一个没动。
**分区本身不是常量**：名字、X/Z 在设置弹窗的"分区设置"格里改，增删也在那儿，改动存同目录 `分区.json`
（`key` 是内部标识，改名不动 key）；落区默认按档位（`ZONE_OF_TIER`），设备行里"分区"那一格可逐台手动钉住
（存进清单第 8 个字段；`serve.mjs` 只校验它"长得像 key"，有没有这个区由页面按 `分区.json` 判）。
删掉一个分区时，钉在它里的设备回到"按档位自动落区"，不会跟着分区一起消失。
新分区落在第一个空着的候选位（3 列 × 5 行的整间距网格），**占位判断按"盒子会不会压到"算**
（`|Δx| < 区宽 && |Δz| < 区深` 即算冲突）：默认摆位是半间距错开的，只比中心点的话新分区会正好叠在算力集群身上。
每个区在地面上立八个角的**木箱角铁**（`createCornerBrackets`，8 角 × 3 臂 × 2 层 = 24 件）+ 一块区名
（`.zlbl`，11px、字距 .18em、不吃鼠标事件）——
**没有这两样，"分了区"在屏幕上是不成立的**：只有四堆机器挨着，看不出是四个区还是摆歪了。
实测（八台四区、默认摆位）：地图左右 9.7 m × 前后 11.4 m，全景距离照包围球现算（16:9 下约 13.0 m），
上限 `MAX_READABLE = 16000` 只挡"分区被挪得很远"这类极端情况。
**全景距离不写死了**（`fitOverview()`）：台数是用户说了算的（增删设备就变），所以每次重造那一排
就按当前实际跨度用画面 fov 现算一次（左右进画面、上下进画面，取大的再乘 1.18 余量），窗口 resize 也重算。
**八台（带外设那页）实测 18,959 mm、九台（净机箱那页）实测 12,689 mm**；原来五台时写死的 9000 在八台下会把最左最右切在画面外。**雾的起止跟着这个距离走**
（`near = dist×1.15`、`far = dist×2.4`）—— 原来写死 20000 起雾，八台一排时整排会被"吞进黑里"，那不是层次是看不见。
**标注从三行压成一行**（名字 + `● 分级 74%`）：八台一排时每条两百来 px 宽，横着排不下，
叠成一坨等于全看不见；包围盒那一行改成**这台被聚焦时才展开**（`.pin`），
没用 `:hover` 是因为标注整块是 `pointer-events:none`（否则会把拖视角的鼠标事件吃掉），悬停压根收不到。
净机箱那页同理（九条），并且奇数条往上错一行。
右边一个齿轮按钮（内联 SVG，不引任何外部图标/字体）。齿轮点开是屏幕正中一个标题为"设置"的对话框，
左右布局：左窄条是分类（第一项 **设备设置**），右边是**折叠式设备列表**——一台一个 `<details>`：
折起来只读身份（名称 / 档位 / 电源 / 地址填没填 四枚 chip），展开才编辑
（名称、档位、电源、系统、**连接地址 / 用户名 / 密码**）。同一时刻只展开一台，
互斥挂在 `summary` 的 click 上而不是 `toggle` 上（`toggle` 是异步派发的，靠它会慢半拍、能同时开两台）。
**连接三格（地址/用户名/密码）现在真的被读了**：**地址 + 用户名**填了 = 这台走 SSH 抓一帧，
缺任一个 = 模拟数据（**密码可以是空的**：办公那几台 Windows 就是"账号 user、不设密码"，
2026-09-23 晚把判据从"三格全填"改成这样）。
**走哪条抓法不看这一页，看清单里的"系统"那一格**：Windows → PowerShell（`-EncodedCommand`，数据取自 CIM）、
Linux → sh；抓回来的 frame 里 `cpuPct`（Windows 直报占用率）与 `load1`（Linux 负载均值）都在，
页面统一走 `framePct()`，别在两处各算一遍。细节见 §八。
密码按用户 2026-09-23 的明确许可**明文存进同目录 `设备清单.json`**（原来那句"只活在内存里、刷新即清空"已作废，
详见 §七）。左边那条分类栏现在有五项：**设备设置 / 分区设置 / 脉冲效果 / 地面与雨 / 采集频率**（后三项都在 §八）。
**弹窗是定高的**（`height: min(700px, 100vh - 48px)` + `.db{flex:1;min-height:0}`，面板自己 `overflow-y`）：
五块面板内容长短差很多，原来用 `max-height` 的话切一次分类弹窗就跟着放大缩小一次，读着像抖动
（实测五个分类的弹窗高度恒为 700 px、面板可视高 657 px，切来切去一个像素不动）。
**脉冲效果格右上角一颗总开关**（`PULSE_SETTINGS.enabled`，跟那几格滑杆同一份 `PULSE_SETTINGS`）：
关掉 = 立刻停发**并且把还在飞的粒子一起 dispose**，不等它们跑完寿命 —— 慢收尾看着像开关没生效。
**设置这几格的值存在同目录 `设置.json` 里**（2026-09-23 起：文件是真源，页面启动读它、改动 400 ms 去抖写回它、
每 5 秒再读一次，所以部署成看板后改这个 json 墙上几秒就变；`localStorage` 降级成 `file://` 没服务时的兜底）。
三组 `pulse` / `ground` / `monitor`，键名就是代码里那些名字 —— 移植时这几个常量（`PULSE_SETTINGS` /
`PULSE_LIMITS` / `MONITOR_SETTINGS` / `MON_LIMITS`）是**范围与默认值的唯一真表**，服务端只校验形状。
**地面与雨格里是另外两颗独立开关**（`rippleEnabled` / `rainEnabled`，2026-09-23 用户点名要"跟脉冲互不牵连"）：
脉冲关了脚下安静，涟漪地面与二进制雨照旧；涟漪关了当帧清空所有活环并把地面抹平。细节见 §八"地面与雨"。
⚠ 这条"互不牵连"2026-09-23 那版只对雨成立：涟漪当时仍挂在脉冲爆发的队列里（唯一的 `addRipple` 调用点在
`if (!enabled) return` 后面），所以关脉冲 = 地面一直平。**2026-09-24 已修**：涟漪改走自己的 `stepRipples` 节拍。
移植时如果只搬地形不搬这颗节拍源，就会把这个旧毛病一起搬过去。涟漪开着时地面还有一层自己走的底波（`BREATH`），
所以"关涟漪"必须连底波一起停（当帧抹平），否则关了还在荡。
⚠ 地面的两颗旋钮（`dotSeg` 密度 / `dotSizeMm` 点径，2026-09-24 加）不是建一次就固定的：
`RippleTerrain.syncDots()` 每帧对比"设置里的值"和"当前几何的段数 / 材质的点径"，段数不一样就整张重建
（新的 `PlaneGeometry` + 新 color 属性 + `rowLists`/四条因子表都按新段数重开，旧几何 `dispose()`），
点径不一样就只改 `material.size` 一个数。所以 `seg`/`step`/`rowLists`/`b1x…` 全是**实例上的、随段数走的**，
写死 `181`、`GROUND_SEG`、`0.7 * GROUND_S` 任一处都会漏。
段数只换采样分辨率：涟漪高度、环宽、波长公式全在参考单位里，一个数不跟着段数变。
↑↓ 删除 三个按钮在 summary 里，必须 `preventDefault()`，否则点一下反而把那台展开了。
每行还多一枚 **◎ 定位**：交换机整机只有 25 mm 高、路由器 270 mm 宽，八台一排的全景里用鼠标点 3D 基本点不中，
所以列表里给一个直达的（点它 = 走跟双击同一条 `focusStation`）。
改名 / 换档位 / 开关机 / 换系统 / ↑↓ 排序 / 添加 / 删除，每一项都直接动场景里那一排
（台数、左右次序、每档用哪套几何全部由这张列表派生，不存在第二份名单）。
密码框仍然是 `type=password`（屏幕上不回显），`window.__hm()` 探针仍然只报"这台是模拟/待抓/实测"，
**不回显地址与凭据**。
只有第一组（带外设）有齿轮；第二组净机箱那页只有 header。
**双击某台设备 = 把那台拉到屏幕正中并拉近**（目标取那台的包围盒中心、距离按包围球对画面 fov 现算，
所以每档近的量不一样，不是写死的数）；**"正中"指的是面板左边那块可视区的正中**，不是整屏正中：
相机沿屏幕右方向平移 `(面板宽 + 12)/2` 像素对应的世界距离（truck，不改朝向），
取景的横向 fov 也按剩余宽度算，所以面板越宽机器越小、但不会被面板压在下面。每帧现算，拖宽/收起都跟着走。双击空白 = 回到全景；滚轮/捏合会立刻打断这段飞行；
"重置视角"仍然是瞬回全景。**双击聚焦的同时，屏幕右侧出现一块性能看板**，五节从上到下：
CPU / 内存 / 显卡 / 磁盘 I/O / 网络。这五节由**一张配置表 `RES` + 一个通用渲染器**驱动
（`PANEL_ORDER` 决定顺序；加一个资源 = 往 `RES` 添一条，不再各写一遍 DOM）：
每节 = 抬头（标题 + 单位计数 + 可选视图按钮）+ 四个总览格 `stats` + 若干卡（`big` 大数 / `bars` 带标签占用条 /
`foot` 脚注 / 可选 `spark` 内嵌曲线）+ 可选 `summary` 负载均衡条；点卡片展开该条的 `detail` + 历史折线 + `threads`。
硬件数量按档位在 `TIER_HW` 里给（cores / gpus / disks / nics / mem）。
**填 0 的那一项 = 这节压根不建**（交换机只剩"网络"一节、路由器 CPU+网络、NAS 无显卡），
判据 `panelKeys()`、重建用 `panelSig()` 签名比对 —— 不比对的话每一拍都会把整块面板重做，
把用户点开的卡片选中态冲掉（这条实测过：聚焦交换机后点一张卡，等 2.2 s 跨两拍，`.sel` 仍在）。
节奏与色阶照用户给的第二版参考：`usage += (target-usage)*0.32`、频率 `*0.25`、温度 `*0.10`、磁盘/网络带突发、
一拍默认 3 s（采集频率那格可改）；使用率色阶 `hsl(145→0 72% 50%)`、温度 `hsl(195→0 80% 55%)`、速率走 `fmtSpeed` 自动换 KB/MB/GB。
**这两条色阶是算出来的 HSL、不是 palette 键**，移植时要么走 `lib/palette.js` 要么先问过（仓库有"颜色只许降不许升"的预算）。
看板**没有可见滚动条**（`scrollbar-width: none` + `::-webkit-scrollbar{width:0}`）但滚轮/触控板照滚；
**左缘一条竖柄可拖宽度**（默认给到上限 620 px，范围 288~620 且不超视口；window 级 `pointermove`，
拖过的值才存 `localStorage["hm.perf.width2"]`，默认值不落盘）。
CPU 小卡**一行最多 4 个**（`minmax(max(78px, (100% - 15px)/4), 1fr)`，栏窄了自己退到 3/2 列）。
核数还有一道总闸 `CORES_CAP = 6`（"一般机箱用不到那么多"）：五档的卡片数全部钳在 6 张以内，
`TIER_HW` 里保留各档真实核数（12/6/16/16/24），要放开只改这一个常量。
右上角**暂停**钮真的挡住 `step`（不是只改文字）。
**数值全是本地随机游走，没接任何真实指标**，看板底部就写着这句。
它跟着聚焦的那台走：改名 → 标题立刻跟上；关机 → 五节的总览/卡/汇总条全部归零成 `—`／"关机，无数据"；
双击空白 / 重置 → 整块收起。这块只加在第一组（带外设＝单机详情那页）；第二组净机箱那页是刻意无状态的剪影架
（连屏幕内容层都藏着），放一块活的指标板会自相矛盾，要就整段搬过去。页面末尾留了个只读探针 `window.__hm()`
（背景标签页 rAF 不跑时靠它核对列表与场景的对应关系），不需要就整段删掉，它对画面没有任何影响。

## 六、模块导出

- `chassis-geometry.mjs`（以前在素材目录里叫 `set2`）：9 个模型函数（`laptopClosed` `laptopOpen` `chassisITX` `chassisMATX` `chassisATX` `chassisEATX`
  `nasQNAP` `switch8` `routerAX`）+ 1 个 helper（`screenContent`）。helper 要传屏幕宽高，**不是模型**；
  无参调用会抛 `TypeError`，别把它当模型遍历。
- `desk-geometry.mjs`（以前叫 `set1`）：8 个模型函数（`monitor24` `keyboardFull` `mouse` `deskLaptop` `deskITX` `deskMATX` `deskATX` `deskEATX`），
  其中机箱与笔记本直接从 `chassis-geometry.mjs` import 复用，没有第二份几何。
- 两个模块顶层都不碰 `document` / `window` / renderer，node 可直接 import。它们要的 THREE 一律来自
  `src/three.mjs` 那一份：node 里它走 `node_modules/three`，同样不碰 `document`（只有两个 CDN 都取不到时
  它才去写页面的状态条）。**别在别的模块里再 `import * as THREE from 'three'`**，那样兜底只覆盖一处。
- 加一档的固定动作（这次加 NAS / 交换机 / 路由器走的就是这六步）：`chassis-geometry.mjs` 加常量 + 模型函数
  → （要带外设才在 `desk-geometry.mjs` 加 `deskXXX()`，纯设备不用）→ `inject-geometry.mjs` 的 `G2_NAMES`
  + `verify-geometry.mjs` 的 `G1_NAMES` 各加一项（`verify` 的 `SPEC` **只在"包围盒就等于规格数"时才加**，
  routerAX 那种含天线的就不加，见 §一之二）
  → 跑 `npm run check`，看 ② 逐件差异 0、③ 同侧重合 0、17 个模型规格全 OK
  → 页面 `TIERS` 加一条（`chip` 短名 / `label` 全名 / `make`），`TIER_HW` 补一行硬件数
  （**没有的东西填 0，那节就不建**，别编）→ `serve.mjs` 的 `TIERS` 白名单 + `DEFAULTS` 各加一项，
  `设备清单.json` 补一行（用脚本 append，**别整档重写**，那台带凭据的行不能碰）。
